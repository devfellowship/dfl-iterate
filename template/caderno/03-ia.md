# IA no template

A IA trabalha no padrão DevFellowship. O fellow pede o resultado em frase
normal e lê o diff. Texto de commit, de plano e de PR é trabalho da IA.

As skills são o procedimento do agente. O fellow não é obrigado a chamar uma
por uma. Duas paradas são dele: o **aceite** de um plano novo, e a leitura do
diff antes do merge.

## Aceite

Para entidade ou tabela nova, `plan-feature` grava `docs/plans/<slug>.md` e
para. A implementação começa quando o fellow responde com um aceite explícito:
"aceito", "pode executar", "ok, executa".

Entries e tasks são um plano só (`docs/plans/caderno.md`) e um aceite. São a
mesma feature. Plano separado por tabela viraria duas esperas para um diário.

Se a resposta mudar o plano ("sem delete"), a IA regrava o arquivo e espera
de novo.

Correção dentro do que já foi aceito ("o empty state está sem texto") segue
direto, sem plano novo.

## Handoff entre chats

Uma boa ideia, e entra no template. Chat longo custa token e a IA mistura
decisão velha com pedido novo. A skill `handoff` troca esse histórico por um
arquivo curto.

- Arquivo único: `docs/handoff.md`. Cada handoff substitui o anterior. O Git
  guarda as versões velhas. A IA do chat novo não tem uma pasta de sessões
  para varrer.
- Teto: cerca de 60 linhas. Sem colar código.
- A IA oferece o handoff quando o fellow avisa que vai abrir outro chat, ou
  quando uma fatia ficou pronta e a conversa já está longa.
- No chat novo, "continua a partir de docs/handoff.md" faz a IA ler esse
  arquivo e os caminhos listados nele, e executar o próximo passo. Sem
  reexplorar o repositório.

Formato:

```md
# Handoff

- **Branch:** ana/feat/entries-list
- **Objetivo:** lista de entradas com criar e apagar
- **Plano:** docs/plans/entries.md — aceito em AAAA-MM-DD
- **Feito:** schema de entries; entries.service.ts
- **Falta:** hooks; EntriesPage; review; PR
- **Próximo passo:** criar useGetEntries, useCreateEntry e useDeleteEntry imitando o perfil
- **Abrir só:**
  - docs/plans/entries.md
  - src/services/entries.service.ts
  - src/hooks/useGetProfile.ts
  - src/lib/queryKeys.ts
```

O chat novo recebe este prompt, também escrito pela skill:

```txt
Continua o caderno a partir de docs/handoff.md.
Faz só o próximo passo. Não releia o repositório.
```

## Skills

| Skill | Faz | Para quando |
|---|---|---|
| `git-flow` | Atualiza a `main` e abre `<usuario>/<tipo>/<slug>` | A branch existe |
| `plan-feature` | Grava `docs/plans/<slug>.md` | Sem o aceite. Não implementa |
| `schema-rls` | Acrescenta tabela idempotente com RLS e `auth.uid()` | Não altera `profiles` |
| `new-service` | Service da entidade do plano aceito | Sem React; mapper; `throw` no erro |
| `new-query-hook` | Lista types, services, queryKeys e hooks antes de criar | Key repetida se estende; entidade fora do plano gera pergunta |
| `new-mutation-hook` | `useMutation` invalidando a key do GET | Não inventa key |
| `wire-page` | Página consome o hook, com pending, erro + retry e empty | Sem client do Supabase na página |
| `review-diff` | Confere a rubrica e a segurança no diff e corrige o bloqueio | Achado bloqueante fica resolvido antes do PR |
| `open-pr` | Título Conventional Commits e corpo no template | Texto escrito pela IA |
| `debug` | Lê o erro de `tsc`, lint ou Supabase, corrige a camada dona e roda `npm run check` | Não reescreve a feature |
| `handoff` | Regrava `docs/handoff.md` no formato acima | Não começa feature nova |

Depois do aceite, a ordem natural numa branch só é: `git-flow`, `schema-rls`,
`new-service`, `new-query-hook`, `new-mutation-hook`, `wire-page`,
`review-diff`, `open-pr`. Vários commits. Um objetivo.

## O que a IA escreve sozinha

- `docs/plans/<slug>.md`
- commits
- corpo do PR: Summary, What was done, How to verify (o roteiro de demo)
- comentário de review, quando pedirem: pontos fortes, ajustes antes do merge, sugestões soltas
- `docs/handoff.md`

## Economia de contexto

Vale em todo turno, também escrita no `AGENTS.md`:

- Ler a fatia ouro e os arquivos do pedido. Não varrer o repo.
- Key que já existe se estende.
- Um objetivo por turno. Diff mínimo.
- Handoff no lugar de repetir a conversa inteira.
